# 项目声明边界

## 已实现后才能陈述

- “基于 LangGraph 构建带条件路由的多智能体匹配流程。”
- “将岗位条件与候选人原文证据绑定，使用确定性评分生成可解释排序。”
- “按硬性条件、加分项和上下文分组计分，避免冗长JD的上下文条目靠数量稀释硬性要求。”
- “对弱证据、硬性条件缺失和敏感属性进行冲突复核与人工转交。”
- “支持招聘人员在排序前确认岗位条件，并记录确认状态。”
- “基于模型摘要、提示词版本和输入哈希复用本地模型结果。”
- “通过2路受控并行和选择性LLM复核，将固定8人无缓存链路由265.08秒降至182.286秒。”
- “通过规则质量门控只将3/8份候选人材料送入LLM，将同一固定演示链路进一步降至76.744秒，排序保持一致。”
- “对6种已知提示注入模板完成确定性回退验证。”
- “将长耗时分析提交到单机后台任务，并在前端展示节点级轮询进度与最终结果。”
- “实现管理员预创建账号、管理员/招聘人员角色权限、持久会话和关键业务操作审计。”
- “通过自动化测试和固定演示集验证端到端链路。”

## 当前不能陈述

- 企业级生产部署或真实企业采用；
- 自动招聘、自动录用或自动淘汰；
- 已接入招聘网站、ATS 或企业私有简历库；
- 公平、无偏或符合法律合规要求；
- 演示数据上的排序指标代表真实业务效果；
- 系统拥有招聘专家级判断能力。
- 能够防御所有提示注入或满足企业级安全要求；
- 首次批量LLM推理达到生产级吞吐。
- 后台任务具备跨进程、跨机器或重启恢复能力；
- 已实现Redis/Celery消息队列、分布式调度或WebSocket实时推送；
- 已实现企业SSO、MFA、多租户隔离、账户锁定或完整企业IAM能力；

## 仍需独立人工标注后再补充

- 独立测试集规模；
- 排序指标与基线提升；
- 证据引用正确率；
- 冲突复核带来的无依据结论下降；
- 配对敏感属性测试的一致性结果；
- 真实中文简历上的抽取与排序效果；
- 不同标注者之间的一致性；
- 真实招聘场景中的端到端时延与并发容量。
