# 候选人画像复用与反事实审计

## 架构边界

候选人处理拆成两个不同阶段：`candidate_profile_agents`只从脱敏后的简历正文生成岗位无关画像；`job_conditioned_evidence_verifier`针对当前JD所需技能执行原文精确核验，不调用LLM。画像缓存键包含候选人ID、脱敏正文、实际模型摘要和解析版本，岗位文本不进入缓存键。

姓名、电话、邮箱以及显式性别、年龄、国籍、婚姻等身份行在模型调用前删除。保留的项目、工作、教育和技能行不改写，因此证据引用仍必须是原始简历的连续子串。提示注入检测在脱敏前针对完整原文执行；命中时跳过模型并进入确定性路径。

## 多岗位复用基准

- 范围：3个岗位、8份虚构演示简历，共24个人岗组合；Qwen3-4B，2路并行。
- 逐岗位解析参考调用数：24。
- 岗位无关画像冷缓存调用数：8，减少16次，即66.67%。
- 冷缓存画像耗时：179.507秒；热缓存8份画像复跑：0.055秒。
- 热缓存命中：8/8；冷/热画像完全一致；证据原文有效率100%。

这是固定演示负载的工程复用验证，不是生产吞吐或排序提升。逐岗位参考调用数是架构调用量对照，没有重复执行24次完整模型推理来制造耗时对比。

## 敏感属性反事实审计

对8份虚构简历分别构造三类变体：不同姓名/性别/年龄、不同姓名/性别/年龄/国籍、不同姓名/婚姻状态/联系方式。规则模式与真实Qwen模式各完成24个候选人级比较：分数不变24/24，三个批次排序均不变。Qwen变体每轮8/8命中同一岗位无关画像缓存，说明显式身份替换没有触发新的模型画像。

该结果只覆盖当前合成材料和显式字段，不能证明系统不存在代理变量、历史标签偏差或真实招聘歧视。系统仍定位为决策支持，禁止自动淘汰或录用。

## 安全回归

6类中英文提示注入模板全部在进入LLM前拦截，6/6输出安全发现，6/6确定性评分与无攻击文本一致。模式匹配无法覆盖所有语义变体，因此该结果不是安全认证。
