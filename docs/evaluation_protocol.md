# 评测协议

## 1. 数据拆分

- 训练/开发数据仅用于技能词典、阈值和权重调整。
- 测试集中的岗位与候选人组合在最终评测前锁定。
- 同一候选人或同一岗位的改写版本不得跨越开发集与测试集。
- 公开招聘历史只能作为弱相关标签，必须记录其来源和潜在选择偏差。
- 合成受控集、招聘历史弱标签集与独立人工标注集必须分别生成报告，禁止合并成一个“准确率”。

## 2. 相关性标签

每个岗位—候选人对使用三级标签：

- `2 高度匹配`：硬性条件基本满足，且核心能力有工作或项目证据。
- `1 部分匹配`：存在可迁移能力或少量核心缺口，需要人工判断。
- `0 明显不匹配`：缺少关键硬性条件，且无足够相邻能力证据。

标注者必须记录依据的 JD 条款和候选人原文，不允许只写总分。

## 3. 指标

### 排序

- NDCG@5：考虑三级相关性和位置权重。
- Precision@3：前三名中标签大于 0 的比例。
- Recall@5：前五名覆盖全部相关候选人的比例。
- MRR：第一位相关候选人的倒数排名。
- 多岗位公开基准除宏平均外，使用岗位级配对bootstrap报告相对基线增量的95%置信区间。

### 抽取与可靠性

- 岗位要求字段 Precision、Recall、F1。
- 候选人技能与年限证据 Precision、Recall、F1。
- 证据引用正确率：引用是否为输入中的连续原文，是否支持对应结论。
- 无依据结论率：标记“已匹配”但没有证据 ID 的条件比例。
- 拒答/转人工覆盖率：输入不完整时是否避免给出确定判断。

### 公平性压力测试

对同一候选人生成配对版本，只替换姓名、性别表达或年龄表达。报告：

- 排序一致率；
- 分数平均绝对变化；
- 推荐状态变化次数；
- 任何变化对应的节点与输入证据。

这些测试只能发现部分敏感性，不等于证明系统不存在歧视。

## 4. 对照与消融

至少比较：

1. 关键词覆盖基线；
2. 仅 Embedding 语义相似度；
3. 单次 LLM 直接匹配；
4. 证据抽取 + 确定性评分；
5. 完整系统：证据抽取 + 确定性评分 + 冲突复核。

只有第 5 组在独立测试集上稳定改善可靠性或排序，才能声称 Multi-Agent 复核有效。

当前中文受控集完成了第1、4、5组；JTH比较关键词、原始多属性与结构化字段匹配。TalentCLEF development难负样本新增了单LLM直接评分、抽取文本检索、证据匹配、JobBERT混合和两阶段融合，但只有5至10个JD，且多种方案未通过留出验证，因此不得声称已完成可泛化的大规模五组消融或Multi-Agent排序稳定优于单Agent。

## 5. 简历指标准入

指标写入简历前必须同时满足：

- 评测脚本、数据版本和模型版本可追溯；
- 独立测试集没有参与阈值调整；
- 失败样本和跳过样本均被统计；
- 指标能在本机重新运行得到一致结果；
- 明确说明样本规模与数据性质；
- 演示集、合成集和真实人工标注集不得混称。
